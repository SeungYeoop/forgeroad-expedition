# 포지로드 다듬기 계획서 (2026-11-28)

요청 31가지(맵 어색한 부분 + 1–28번 + 추가 #29 창고·#30 가방 칸)를 같은 작업끼리 묶어 **빨리 끝나는 것부터** 6단계로 정리했다.
"현재 상태"는 아직 코드를 열어 보기 전에 쓴 추정이다. 각 항목의 첫 작업이 그걸 확인하는 일이다.

---

## 0. 진행 원칙

- **순서**: 1단계 → 6단계. 같은 단계 안에서도 위에서부터.
- **커밋·배포**: 항목 하나가 끝날 때마다 `blue-remake`에 커밋 → main으로 ff → push. `old` 브랜치는 건드리지 않는다.
- **품질**: 빨리 하는 건 군더더기를 줄이는 것이지 품질을 깎는 게 아니다.
  - 그림은 사실적인 바이킹 스타일, 귀엽게 그리지 않는다.
  - 맵·배경·화면 그림은 작업 전에 `docs/reference/maps/README.md`와 ref01–07을 먼저 본다.
- **확인 지점**: 설계 표나 그림을 확인받아야 할 때도 **작업을 멈추지 않는다.** 보내 놓고 다음 항목을 계속하다가, 의견이 오면 반영한다.
- **공통 검사**(항목마다 해당되는 것):
  - natlab: 20지역 × 시드 1–3
  - zoneshot: 콘솔 오류 0
  - foefight: 몬스터 행동
  - 화면 작업은 사진 링크를 보낸다

## 2. 1단계 — 빼거나 막기만 하면 되는 것

### 1-1. #23 오른쪽 위 알림 텍스트 없애기 — S

### 1-2. #5 맵 이름 라벨·돈 라벨 없애기, 돈은 가방에서 — S

### 1-3. #7 몬스터 공격 범위 빨간 표시 없애기 — S
- **찾기**: bkit 행동(slam, charge, beam, dive, lob 등), 지역별 `r<code>.js`, 예전 보스 코드에서 범위 표시를 그리는 호출을 모두 찾는다.
- **처리**: 표시를 지운다. 대신 공격을 읽을 수 있게 **몬스터 자체의 준비 동작**으로 알린다.
  - 지금 있는 준비 프레임이 짧으면 0.1–0.2초 늘린다.
  - 준비 시작 순간 몸이 아주 짧게 밝게 번쩍인다(바닥 표시는 없다).
- **완료 기준**: foefight로 지역마다 범위 공격 몬스터와 정예를 2–3종씩 붙어 본다. 빨간 표시가 없고, 준비 동작을 보고 피할 수 있다.

### 1-4. #4 로딩 중 모든 입력 막기 — S
- 로딩 시작부터 **새 장면 첫 화면이 그려지고 0.3초 뒤까지** 입력 잠금을 켠다.
- 키보드·마우스 처리 맨 앞에서 잠금이면 무시한다.
  - 대상: ESC, 가방, 지도, B(귀환), 스킬, 이동, 클릭 전부.
- 잠금이 풀릴 때 **눌려 있던 키 상태를 초기화**한다. 로딩 중에 누른 키가 끝나자마자 실행되지 않게 하기 위해서다.
- 지역 이동, 거점 진입, 사망 후 부활, B 귀환까지 모든 로딩에 적용한다.
- **완료 기준**: 로딩 중 키를 연타하는 자동 스크립트를 돌린 뒤, 일시정지·가방이 닫혀 있고 캐릭터가 제자리이다.

## 3. 2단계 — 모든 맵 어색한 부분 찾아서 고치기

### 2-0. 맵 검사기 만들기 — M
- natlab 기반으로 `tools/mapaudit.mjs`를 만든다.
- 20지역 × 시드 1–3을 돌려 **문제 종류별 개수 표**와 **문제 위치(좌표)**를 낸다.
- 문제 위치마다 zoneshot을 잘라 사진으로 남긴다. 고치기 전과 후를 비교하기 위해서다.
- 아래 2-1 ~ 2-10 검사를 모두 이 도구에 넣는다. 앞으로 맵을 새로 만들 때도 이 도구로 검사한다.

### 2-1. 사다리 끝이 막힘
- **검사**: 사다리 맨 위로 올라갔을 때와 맨 아래로 내려갔을 때, 캐릭터 몸(가로 1칸 × 세로 2칸) 크기의 빈 공간과 디딜 바닥이 있는지 본다.
- **추정 원인**: 사다리를 늘리는 코드(extrusion)가 지형을 확인하지 않거나, 방 틀끼리 겹친다.
- **수정**(생성기 공통 마무리 단계에 넣는다):
  1. 끝이 막혔으면 출구를 판다.
  2. 팔 수 없으면 사다리를 줄인다.
  3. 그래도 안 되면 사다리를 지우고, 그 구간에 다른 길이 있는지 길찾기로 다시 검사한다.

### 2-2. 위아래 이동문이 맵 중간에 있음
- **규칙**:
  - 위로 가는 문은 맵 **맨 위 3칸 안**, 아래로 가는 문은 **맨 아래 3칸 안**에 놓는다.
  - 좌우 문은 맵 좌우 가장자리에 놓는다.
- **수정**: archi_* 파일마다 출구 위치값을 고친다. 생성기가 규칙을 어기면 경고를 내게 한다.
- **모양**: 위 출구는 천장에 뚫린 통로 끝, 아래 출구는 바닥 구덩이·계단 입구로 만든다. 최종 그림은 5-1에서 그린다.
- 문까지 실제로 갈 수 있는지는 2-9 길찾기 검사로 확인한다.

### 2-3. 천장 몬스터가 공중에 매달림 (+ 땅·벽 몬스터 위치)
- 몬스터마다 붙는 곳을 정리한다: **천장형**(박쥐, 거미, 매달린 것), **땅형**, **벽형**, **비행형**.
- **스폰할 때**:
  - 천장형: 위쪽으로 천장 칸을 찾아 바로 아래에 붙인다.
    - 6칸 안에 천장이 없으면 같은 방 안에서 천장이 있는 자리로 옮긴다.
    - 그런 자리도 없으면 그 지역의 다른 몬스터로 바꾼다.
  - 땅형: 공중에 스폰되면 바닥으로 내린다.
  - 모든 몬스터: 벽 속에 스폰되지 않는다.
- 천장에 붙은 상태의 그림 방향(거꾸로 매달림)도 함께 확인한다.

### 2-4. 횃불·사다리 같은 벽 장식이 맨 앞에 떠 보임
- **장식 분류**:
  - 벽에 붙는 것: 횃불, 벽등, 깃발, 사슬, 벽 덩굴, 선반
  - 바닥에 놓이는 것: 상자, 통, 돌무더기
  - 일부러 앞에 두는 전경: 앞 풀, 덩굴 커튼
- **레이어 순서**를 하나로 고정한다:
  배경 → 뒷벽 → **벽 장식** → **사다리** → 몬스터·캐릭터 → 지형 앞면 → 전경 장식
- 벽 장식 뒤에 뒷벽이 없으면 장식을 놓지 않는다(허공에 횃불 금지).
- 바닥에 놓이는 것은 아래 칸이 단단한지 검사한다(공중 상자 금지).

### 2-5. 아래가 뚫렸는데 물이 떠 있음
- **규칙**: 움직이는 폭포를 뺀 고인 물은 **아래와 양옆이 막힌 곳**에만 있다.
- **검사**: 이어진 물 덩어리마다 아래나 옆에 빈칸(물도 벽도 아닌 칸)이 하나라도 닿아 있으면 "새는 물"로 센다.
- **수정**: 생성기 마지막에 **물 안정화** 단계를 넣는다.
  - 물을 실제로 흘려 보듯 새는 칸을 아래로 내려 고이게 한다.
  - 고일 곳이 없으면 지운다.
  - 결과 수면은 평평해야 한다.
- 폭포는 "흐르는 물"로 표시해서 검사에서 뺀다.

### 2-6. 몬스터가 벽 너머로 나를 알아챔
- bkit `notice`에 **시야선 검사**를 넣는다. 몬스터 눈에서 플레이어까지 칸을 따라가다 단단한 칸을 만나면 못 본다.
  - 발판·사다리·풀은 통과한다.
- 이미 싸우는 중에 시야를 잃으면 3초 동안 마지막으로 본 위치로 간 뒤 포기한다.
- 플레이어에게 맞으면 시야와 상관없이 알아챈다.
- **성능**: 몬스터마다 0.2초에 한 번만 검사한다.

### 2-7. 몬스터 투사체가 초록 상자로 깨짐
- **추정 원인**: 그림을 불러오지 않은 이름으로 투사체를 만들면 Phaser가 대신 그리는 초록 상자다.
  - 다른 후보: 지역을 옮길 때 날아가던 투사체의 그림이 먼저 지워지는 경우.
- **순서**:
  1. 실행 중에 없는 그림 이름이 요청되면 기록하는 장치를 건다.
  2. foefight로 모든 지역의 원거리·범위 몬스터를 공격시키면서 없는 이름을 모은다.
  3. 이름 오타를 고치거나, 빠진 그림을 만들거나, 불러오는 목록에 넣는다.
  4. 안전장치: 그림이 없으면 기본 투사체 그림으로 대신 그린다.
  5. 지역 이동 때 남아 있는 투사체를 먼저 지운다.
- 6단계 효과 시스템(6-3)이 들어오면 그림 불러오기를 그 시스템이 관리한다.

### 2-8. 뒷벽이 지형과 안 맞음 (튀어나옴, 없음, 뚫림)
- **규칙**:
  - 동굴처럼 막힌 공간의 빈칸 뒤에는 **항상 뒷벽**이 있다.
  - 바깥 하늘과 이어진 빈칸에는 뒷벽이 **없다**.
  - 하늘섬 안쪽 방은 섬 윤곽 안쪽에만 뒷벽이 있다.
- **수정**: 뒷벽을 지형에서 **자동으로 만든다.**
  - 바깥과 이어지지 않은 빈칸은 실내로 보고 뒷벽을 채운다.
  - 지형 가장자리는 1–2칸 안쪽까지 뒷벽 테두리를 넣는다.
  - 창문처럼 일부러 뚫은 곳은 표시해서 뺀다.
  - 손으로 뒷벽을 그린 archi_* 파일은 자동 결과와 비교해서 어긋난 곳만 고친다.

## 4. 3단계 — 작은 새 기능

### 3-1. #11 B키 귀환 — M
- **동작**:

  - 움직이거나, 맞거나, 공격하면 취소된다.
  - 완료하면 골드를 빼고, 로딩(입력 잠금) 후 거점에 도착한다.
- **사용 불가**: 전투 중(마지막으로 때리거나 맞은 지 5초 안), 보스 방 안, 거점 안.
- **비용 공식**(숫자는 조정 가능한 상수로 둔다):
  ```
  비용 = (기본 200 + 아이템 수 × 30) × 거리 배수
  아이템 수 = 가방 안 장비 1개당 1 + 재료·소모품 10개당 1 (장착 중인 장비는 뺀다)
  거리 배수 = 1.6 ^ (거점까지 최단 지역 수 − 1)
  ```
  - 예: 거점에서 2칸 떨어진 지역, 아이템 25개 → (200 + 750) × 1.6 = **1520골드**
  - 예: 4칸, 아이템 40개 → (200 + 1200) × 4.1 ≈ **5740골드**
- **맞추기**: 먼저 지금 지역별 한 번 사냥 수입을 잰다. 그 수입의 **25–40%** 정도가 되게 상수를 맞춘다("비싸게").
- **골드 부족**: 시전 막대 자리에 "골드 부족 (필요 1520)"을 띄우고 시전하지 않는다.

### 5-2. #19 레시피 도감 — M

  - 아직 못 얻은 것은 실루엣과 "???", 힌트 한 줄("노랑 지역 상자에서").
- 탭마다 수집률을 표시한다. 저장 데이터에 발견 기록을 추가한다.

### 5-3. #20 전설 레시피가 상자에서 나옴 — M

- **연출**: 상자를 열 때 금빛 기둥이 서고, 두루마리 아이템이 나오며, 중앙 큰 알림(3-4)이 뜬다.

### 5-5. #18 각인·방어구·무기 융합 리메이크 — L
- **분석**:
  - 마법+마법 융합이 좋은 이유를 정리한다(두 성질이 섞인 새 동작, 고유 이름, 전용 그림·효과).
  - 지금 각인·방어구·무기 융합의 목록과 문제(단순 수치 증가 등)를 정리한다.
- **새 기준**: 모든 융합 결과는 다음을 갖춘다.
  1. 고유 이름
  2. **새 동작이나 새 규칙 1개 이상**(% 증가만 있는 것 금지)
  3. 전용 그림
  4. 전용 효과
- **종류별 방향**:
  - 마법+각인: 마법의 동작이 바뀐다(예: 화염구 + 분열 각인 → 세 갈래 화염).
  - 무기+마법: 휘두를 때 마법이 깃든다.
  - 방어구+마법: 맞을 때 반응한다.
  - 무기+각인, 방어구+각인: 무기·방어구의 규칙을 바꾼다.
  - 물속 산소 증가 같은 새 기능(3-3)도 여기서 만든다.
- **순서**: 설계 표를 보내고, 구현하고, 밸런스를 검사한다(같은 티어 마법+마법 융합과 강도를 비교).

### 5-7. #27 알비온식 진짜 지도 — L
- 우리 게임은 지역을 **좌우와 위아래**로 오간다. 그래서 지도는 **옆에서 본 그림 지도**로 만든다.
  - 위쪽: 하늘 구름섬들
  - 가운데: 지상
  - 아래쪽: 지하 동굴
- **격자 없애기**:
  - 지역마다 모양(울퉁불퉁한 덩어리), 크기, 간격을 다르게 하고 위치도 살짝 흐트러뜨린다.
  - 연결은 그림으로 이어 준다: 지상은 길, 위아래는 사다리·밧줄·동굴 통로, 하늘은 구름다리.
- **그림체**: 양피지, 가장자리 그을림, 접힌 자국, 손그림 산·숲·강·탑 아이콘, 지역 이름 서체.
- **기능**:
  - 확대·이동, 현재 위치 깜빡임.
  - 가 본 곳은 색칠, 안 간 곳은 흐린 스케치.
  - 지역을 누르면 정보(이름, 링, 층, 보스 처치 여부, 몬스터 도감 수집률, 귀환 비용 3-1)가 나온다.
  - 빨강 링에는 붉은 밀랍 봉인을 그린다. 거점은 크게 그린다.
- **위치 확인**: 지도 위치는 실제 맵 연결과 반드시 맞아야 한다. 출구 방향을 자동으로 대조하는 검사를 넣는다.

  | 동작 | 프레임 |

  | 사다리 | 4 |
  | 수영 / 물속 정지 | 6 / 4 |
  | 피격 | 2 |
  | 사망 | 6 |

  - 몸통 비틀기와 앞발 디딤이 함께 움직인다.

## 9. 서로 묶인 작업

- **1-3 빨간 표시 삭제** ↔ 몬스터 준비 동작 보강 ↔ **6-4 보스 패턴**
- **2-7 초록 상자** → **6-3 효과 시스템**이 그림 불러오기를 맡으며 최종 해결
- **3-2 티어 선택** → **4-3 상점 리메이크**에서 화면 완성
- **산 아이템 → 가방**, **거점 가방**, **가방 칸 늘리기**를 모두 4-2에서 같이 한다(가방 칸이 적으면 금방 꽉 차기 때문).
- **3-1 B 귀환** ↔ 지금 B키는 운명 보드다. 운명 보드 키를 다른 키로 옮긴다. 예전 귀환 표지석(5초 집중)도 B 귀환으로 대신하고 없앤다.
- **4-2 가방 칸 늘리기** → 3-1 귀환 비용 상수를 다시 맞춘다
- **4-4 창고** ↔ 4-2 가방 패널을 오른쪽에 그대로 쓴다
- **3-4 중앙 큰 알림** → 5-3 전설 레시피, 6-4 보스 처치에 재사용
- **3-5 희귀도 테두리** → 4-1 공통 UI, 5-2 도감, 4-3 상점
- **3-6 시전 준비** → 6-1 애니메이션 + 6-3 효과로 최종판
- **5-1 이동문** ↔ **2-2 문 위치 규칙**, 6-4 보스 방 문
- **5-7 지도** ↔ 3-1 귀환 비용 표시, 6-4 보스 처치 표시
- 6단계 순서를 **애니메이션 → 효과 → 보스**로 둔 이유: 보스가 새 효과와 새 준비 동작을 쓰기 때문에, 먼저 만들면 다시 고쳐야 한다.
